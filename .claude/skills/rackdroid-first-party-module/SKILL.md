# Writing an original (first-party) module pack

`drums/` ("RackDroid Drums") is the template for a plugin pack that is
**entirely original code and art** — no third-party source to vendor, no
licensing surface beyond RackDroid's own GPLv3. Use it as the pattern for
any new first-party pack.

## Structure to copy

```
drums/
  Makefile        desktop VCV Rack build (make dist -> .vcvplugin)
  plugin.json     manifest: slug, modules[] (slug/name/description/tags)
  src/
    plugin.hpp    extern Model* per module + shared DSP helpers namespace
    plugin.cpp    p->addModel(modelX) calls, one per module
    voices.cpp    module implementations (split across files as it grows)
    voices2.cpp
  res/*.svg       panels, generated (not hand-drawn) via a graphics/ script
```

## Key pattern: shared DSP helpers in the header

`drums/src/plugin.hpp` declares a small `rddrums` namespace of reusable
primitives shared by every module in the pack (`OnePoleHP`, `OnePoleLP`,
`ExpEnv`, a xorshift `Noise` generator). New packs should follow the same
shape: put cross-module DSP building blocks in the pack's own namespace in
the shared header, not duplicated per-module-file.

## Widgets: reuse the stock component library only

`drums`'s widgets use only Rack's stock knob/port/screw component classes —
whose SVGs are already original RackDroid `ComponentLibrary` art (see
[[rackdroid-graphics]]) — so the pack "adds no new licensing surface" (see
comment in `drums/src/plugin.hpp`). Don't introduce custom widget graphics
unless necessary; if you do, they must be original art, not copied/adapted
from VCV's CC BY-NC-ND components.

## Panels: generate them, don't hand-draw them

`drums`'s 14 panels are generated by `graphics/gen_drums_panels.py`, which
reuses `regen_graphics.gen_panel()` with a `PANELS` dict of per-module label
positions (knob/CV/bottom labels). For a new pack, either extend that script
or write an analogous one that calls into `regen_graphics`'s panel-drawing
primitives — this keeps visual consistency with the rest of the app "for
free" and avoids maintaining hand-authored SVGs.

## Wiring a new pack into the build

Same as porting a third-party plugin — see [[rackdroid-add-plugin]]'s
"Adding a new CMake plugin target" section: add an `add_simple_plugin` (or
hand-written, if it needs extra deps) target in `native/CMakeLists.txt`,
decide bundled-in-APK vs `.rdmod` side-load, and validate with
`rack_ui_smoke --all-modules` ([[rackdroid-host-smoke]]) before a full
Android build.

## Desktop build (optional, for testing against real VCV Rack)

```sh
cd drums && make dist RACK_DIR=../third_party/Rack
```

Produces `dist/RackDroidDrums-<version>-<os>-<arch>.vcvplugin`, installable
in a real desktop VCV Rack 2 for comparison/testing — useful to sanity-check
DSP behavior outside the Android port layer entirely. Needs `JANSSON_INC` to
resolve (auto-detected from a prior CMake build's FetchContent dir; run a
`cmake` configure first if this fails to find jansson headers — see
[[rackdroid-host-smoke]]).
