# Graphics regeneration pipeline

Why this exists: VCV's stock ComponentLibrary/Core/Fundamental panel art (and
several plugins' own graphics) are **CC BY-NC-ND** — not commercially
redistributable. RackDroid replaces them with **original, drop-in
replacement SVGs** at the same canvas size/filenames, generated by Python
scripts under `graphics/`, so the app can be distributed while the
underlying GPLv3 module code stays byte-identical to upstream. Check
`graphics/NOTICE-graphics.md` for the current licensing status of every
bundled/packaged plugin's graphics before assuming stock art is safe to ship.

## Scripts and what each does

| Script | Produces | Run |
|---|---|---|
| `graphics/regen_graphics.py` | Original SVGs replacing CC BY-NC/ND art (ComponentLibrary, Core, Fundamental, FrozenWasteland, AudibleInstruments, ImpromptuModular, CountModula, GrandeModular, etc.) at canonical (amber) palette | `python3 graphics/regen_graphics.py` (no args; hardcoded `jobs` list in `__main__`, optionally pass a substring of a job's source path as `argv[1]` to regenerate only matching jobs) |
| `graphics/gen_themes.py` | Non-canonical color theme variants (`blue`, `emerald`, `violet`) under `graphics/themes/<theme>/`, by calling `regen_graphics.set_palette(theme)` then reprocessing a reduced job list | `python3 graphics/gen_themes.py` (no args; restores palette to `"amber"` when done) |
| `graphics/gen_drums_panels.py` | The 14 RackDroid Drums panel SVGs, written directly to `drums/res/` | `python3 graphics/gen_drums_panels.py` |
| `graphics/webp_thumbs.py` | Converts `browser-thumbs/*.png` to lossy `.webp` (q80, ~60-70% smaller), deletes the PNGs | `python3 graphics/webp_thumbs.py` (needs Pillow: `pip install Pillow`; hardcoded to operate on `graphics/browser-thumbs/`) |

## Typical workflows

**Regenerate everything after an upstream Rack/plugin version bump**, or
after editing the "warm studio" palette constants at the top of
`regen_graphics.py`:
```sh
python3 graphics/regen_graphics.py
python3 graphics/gen_themes.py
python3 graphics/gen_drums_panels.py
```

**Add a new color theme**: add its name to `THEMES` in
`graphics/gen_themes.py` (currently `["blue", "emerald", "violet"]` — amber
is canonical and not regenerated by this script, it lives in the committed
`system-res`/`fundamental-res`/`drums/res` directly), add a matching palette
override in `regen_graphics.py`'s `THEMES` dict (accent pair cascades to
knob pointers/switch nubs/LEDs/header strip automatically), then run
`gen_themes.py`. Wire the new theme name into the Kotlin side
(`AppTheme.kt`'s presets) and `app/build.gradle.kts`'s per-theme `from(...)`
blocks in `packSystemAssets` so it gets packed into `system.zip` under
`themes/<name>/`.

**Regenerate module-browser thumbnails** after adding/changing modules:
```sh
# build with -DRACKDROID_HOST_UI=ON first, see rackdroid-host-smoke
./build-host-ui/rack_ui_smoke 1 --export-thumbnails graphics/browser-thumbs
python3 graphics/webp_thumbs.py
# then commit graphics/browser-thumbs/*.webp
```
Where a plugin's regenerated thumbnails end up shipping depends on whether
it's bundled or side-loaded — see [[rackdroid-add-plugin]]: only
Core/Fundamental/RackDroidDrums thumbnails ride in the base APK
(`thumbnails.zip`); every other plugin's `graphics/browser-thumbs/<slug>/`
is packed into its own `.rdmod` by `scripts/make_rdmods.sh` instead, never
into the APK.

## Constraints to respect

- `regen_graphics.py` only extracts **facts** from the originals it replaces
  (canvas dimensions, functional text labels like "FREQ" — not
  copyrightable) — never copy actual path/shape data from a CC BY-NC-ND
  source file into the regenerated SVG.
- nanosvg (the runtime SVG renderer) supports gradients but **not**
  filters/blur — all depth/shading tricks in `regen_graphics.py` use
  gradients and concentric shapes instead. Keep new panel art within that
  constraint or it will render wrong on-device even though it looks right
  in a desktop SVG viewer.
- Bogaudio's graphics are CC BY-SA 4.0 and are **kept as-is, not
  regenerated** (compatible license, per `graphics/NOTICE-graphics.md`) —
  don't assume every plugin needs the regen treatment; check the notice file
  first.
- After exporting thumbnails, always run `webp_thumbs.py` **before**
  committing — `ModuleBrowserSheet.kt`'s loader specifically expects `.webp`
  extensions, not `.png`.
